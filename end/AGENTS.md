# end lab: an Endstone plugin (Python) proven on a real Endstone server. `node lab.mjs end <cmd>` once, then `node lab.mjs <cmd>`
1. `new <n> "Title" "<request>" desc="<what it does>"` → plugins/<n>/: pyproject.toml, src/endstone_<n>/plugin.py (a command + a join handler), tests.txt, TASK.md (`--cpp` C++, `--bp` packs).
2. Write plugin.py and tests.txt (syntax and `@A` real-player actions: ../AGENTS.md). What only Endstone can do, as 20 working plugins in plugins/: `help ideas`.
3. `go` = pyright on Endstone's stubs + lint → tests on a fresh server → QA (3 players, rejoin, /reload, restart, perf, still enabled, then every command fuzzed) → dist/*.whl. Fix what it prints until `DONE`.
Plugin: class attrs `api_version = "0.11"`, `prefix`, `commands = {"n": {"description": "..", "usages": ["/n <x: int> [y: str]"], "permissions": ["p.command.n"]}}`, `permissions = {"p.command.n": {"description": "..", "default": True}}` (`"op"` = operators); pyproject `[project.entry-points."endstone"] n = "endstone_n:Class"`. `on_enable`/`on_disable`; `on_command(sender, command, args) -> bool` (False prints the usage). Events: `self.register_events(self)` + `@event_handler def on_x(self, e: PlayerJoinEvent)`; cancel with `e.is_cancelled = True` (never name a handler `on_command`: that is the command method). The API is server-thread only: `self.server.scheduler.run_task(self, fn, delay=, period=)`; no sleep or blocking I/O on it (a thread may compute, then run_task back); files in `self.data_folder`; PyPI: `lib add <pkg>`. Look up, do not guess: `api <Class|Class.member|?word>`.
Expectations under a `py` line check its value only (`@A ...` ones still the section). Test lines besides console commands and `@A` actions: `py <code>` in the server (`return x`: a value prints short: a str as itself, numbers plain, True/False, None as -, lists and tuples as `["B","A",0]` (strings inside quoted), dicts as `{k=v}`; or return an f-string; more lines: `\n`, or the next lines indented by 2 spaces (those 2 are removed: a nested block indents 2 more); names server plugin p(name) cmd("..") dim() inv(p) block(x,y,z) S) · `serverping` (the server list line) · `events on [Name]` · `packets on [name]` / `packets drop <name> [n]` · `fuzz <command> [n]` · `lag <ms>` · `watch <expr>` · `trace <file.py:12> [expr]` · more: `help py|events|packets|reload|cpp|server|player|tests`.
Usage parameter types the plugins here use: int float str message (the rest of the line), an enum `(a|b)<mode: Mode>`; a player as `<player: str>` (then `self.server.get_player(name)`). Permissions: the lab's players are operators; `deop B` makes B an ordinary player for a "not allowed" section. `restart` keeps the plugin's data folder and the world; players rejoin.
World: flat (grass y=-61), x,z -32..31 loaded, survival, noon, no mob spawns.
