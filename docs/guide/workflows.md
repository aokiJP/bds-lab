# 使い方と自動化（作らせる・配る・自動操縦・保守・品質）

[README](../../README.md) から分けた詳細です。全体の地図は [ARCHITECTURE.md](../ARCHITECTURE.md)。

## 使い方は 3 通り

**1. ターミナルを使える AI に頼む（Claude Code・Codex・Gemini CLI・Copilot・Cursor など）**
このフォルダを開いて「○○するアドオンを作って」と頼むだけです。AI が読むのは `AGENTS.md`（約 1,200 token）だけで、あとは次の 3 手で完成します。

```sh
node lab.mjs bds new ruby "Ruby Shop" "頼まれた内容" desc="ルビーでダイヤが買える"   # 雛形（TypeScript・BP/RP・日英の言語ファイル・kit）
node lab.mjs add item lab:ruby "Ruby" ja=ルビー tex=gem:e0115f max_stack_size=16   # アイテム・テクスチャ・名前を一度に
node lab.mjs go                                        # 型検査 → 実機テスト → 品質チェック → .mcaddon
```

**2. ラボに AI を呼ばせる（全自動）**

```sh
node lab.mjs make "ルビーを追加して、/lab:shop でダイヤと交換できるようにして"
```

ラボが AI を呼び、`go` が `DONE` になるまで回して、使ったトークン数を表示します（`bench/ranking.json` にも記録）。AI の呼び方は自動で選ばれ、`--via` で指定もできます。

- **どのラボで作るかも自動**：依頼文から、BDS のアドオンでは届かないもの（HTTP サーバー・ファイル・SQL・プレイヤーごとのボスバーや言語・ログイン拒否・パケット・バニラコマンドの横取りなど）なら Endstone、NBT や LeviLamina を名指しされたら LeviLamina を選びます（理由を 1 行表示。`--lab bds|end|ll` で指定も可）。
- **変更**：`node lab.mjs make -a ruby "ルビーを5個に"` は既存のものを直します。今のテストは弱めずに通したまま、変更点のテストを足します（TASK.md の `## Changes` に記録）。
- **AI プレイテスト**（`--playtest`）：できあがったら、**作った AI とは別の AI** が本物のサーバーで遊んで壊しにいきます（再参加・フォームを閉じる・2 人同時・負の数・再起動など）。見つけた不具合は「今は失敗するテスト」として tests.txt に足され、まっさらなサーバーで本当に失敗するものだけが `tests.lock` に固定されます。作った AI はそれを通るまで直します（固定したテストは書き換えも削除もできず、依頼に反する指摘には `dispute` で理由を残します。理由は TASK.md に残るので人が判断できます）。既存のものを鍛えるだけなら `node lab.mjs make -a <名前> --playtest`。
  - 例：わざと 2 つ不具合（再参加するたびにルビーが増える／フォームを閉じるとエラー）を入れたショップで、プレイテスト AI が 2 つとも見つけ、作る側の AI が両方直して `DONE` になりました（計 447,513 トークン、うちプレイテスト 286,779、214 秒）。
  - プレイテストで見つかりやすい種類の不具合は、ラボの品質チェックにも組み込みました（フォームを閉じたときのエラー、依頼が「初めて参加したとき」なのに再参加でもう一度もらえるアイテム）。トークンを使わずに毎回調べます。
  - 品質チェックでは見つからない不具合（ルビー 1 個でもダイヤが買える／買った人ではなく別のプレイヤーにダイヤが渡る）も、プレイテスト AI が 2 人で遊んで見つけ、作る側の AI が直しました。そのとき AI が書いたテストの落とし穴（空の持ち物に `clear` するとエラー扱い、別のプレイヤーの行まで見てしまう否定チェック）も、ラボ側で直しました（中身のない後片付けはエラーにしない、`js` の下の期待はその値だけを見る、壊れたテストは固定しない）。直したあと同じ課題をもう一度走らせると、2 つとも見つけて直し、異議なしで `DONE` まで 919,046 → 407,734 トークン（24 → 13 ターン、462 → 256 秒）になりました（`node bds/bench/bench.mjs playtest exploit`）。

| `--via` | 必要なもの | 特徴 |
|---|---|---|
| `anthropic` | `ANTHROPIC_API_KEY` | ラボ内蔵の最小エージェント（道具 4 つ・プロンプトキャッシュ）。**最もトークンが少ない** |
| `openai` | `OPENAI_API_KEY`（+ `OPENAI_BASE_URL` でローカル LLM や互換サーバー） | 同じ最小エージェントを OpenAI 互換 API で |
| `claude` / `codex` / `gemini` | その CLI | 手元のエージェント CLI に任せる |
| `"コマンド {prompt}"` | 任意の CLI | 上以外のエージェント |

`--model` でモデル、`--name` でアドオン名、`--js` / `--stable` で雛形を選べます。

**GitHub の Issue から作る**（`.github/workflows/ai-make.yml`）
リポジトリの Secrets に `ANTHROPIC_API_KEY` を入れ、Issue に `make` ラベルを付ける（またはタイトルを `make: ...` で始める）と、Actions が `make --playtest` で作り、テストと品質チェックに通ったものをブランチと Release（`.mcaddon` など）にして、Issue に結果・使い方・トークン数を返信します。その Issue に `/make <変更内容>` とコメントすると同じものを直します。動かせるのはリポジトリのオーナー・メンバー・共同編集者だけです（API のトークンを使うため）。

**3. チャットだけの AI に頼む（ChatGPT・Claude・Gemini の画面など）**
zip を添付して「README.md に従って ○○ を作って」と送り、手元でも展開しておきます。AI の返事にあるパッチ（`===== bds-lab patch` で始まるブロック）をコピーして `verify.command`（Mac）/ `verify.cmd`（Windows）をダブルクリック（Linux は `./lab.sh verify --watch`）。本物のサーバーで確かめた結果がクリップボードに入るので、そのままチャットに貼ります。ウィンドウを開いたままなら、次からはパッチをコピーするだけです。`DONE` / `test: PASS` で完成、配布物は `dist/` にあります。

## 改良した bds-lab を人に渡す（`share`）

自分のアドオンや鍵を含めずに、**bds-lab 本体だけ**をリリース版の zip にします。

```sh
node lab.mjs share              # dist/bds-lab-v1.0.1.zip（+ .sha256）。版は自動で 1 つ上がる（--bump minor|major|none）
node lab.mjs share --release    # GitHub の Release lab-v1.0.1 にも出す
node lab.mjs share --dry        # 入るファイルの一覧だけ
```

- **入るもの**：エンジン・説明書・テスト・ワークフロー・ラボの見本（`common/data/samples.json`：`help ideas` の Endstone 20 個・LeviLamina 14 個と app ラボの `jsonui_demo`）。
- **入らないもの**：自分のアドオン・プラグイン・mod、サーバーやキャッシュ（BDS は Mojang のもので配れません）、テストの結果、`.env` / `.env.local` やトークン、パッチの残り。自動操縦の記録（台帳・backlog・教訓・設定）は空の状態で入ります。
- **漏れ防止**：入るファイルを全部、鍵の形（Anthropic / OpenAI / GitHub / Slack / Discord / AWS / Google の鍵、秘密鍵）と **自分の `.env` に書いた値そのもの** で調べ、1 つでもあれば何も書きません（値は画面にも出しません）。`node lab.mjs maint` の点検も同じ調べ方になりました。
- **単体で動くか確かめてから残す**：できた zip を空のフォルダに展開し、その中でラボのテスト（docs・dev・kit・make・ci・auto・update・share）を回します。1 つでも落ちたら zip は消します。
- 同じ中身なら同じ zip（sha256 が一致）。`VERSION` と `CHANGES.md`（前回の lab-v タグからのコミットと、自動操縦がラボ本体に入れた改良）も更新します。
- 受け取った人は展開して `node lab.mjs start`。すでに使っている人は `node lab.mjs update bds-lab-v1.0.1.zip` で、自分のアドオン・キャッシュ・鍵・自動操縦の記録と設定を残したまま本体だけ新しくなります。
- GitHub では `.github/workflows/share.yml` を手動で実行。自動操縦も、ラボ本体を改良したあと自分で `share --release` します（仕事の種類 `share`）。

## 全部 AI に任せる（自動操縦 `auto`）

頼まなくても、**何をやるかを AI が自分で決めて、作って、直して、確かめて、main にマージして、配布まで**します。人がやるのは「上限を決める」と「止める」だけです。

```sh
node lab.mjs auto                 # 次にやること（AI が選ぶ候補と点数）・今日のトークン・種類ごとの成績
node lab.mjs auto run --forever   # 自動操縦を回し続ける（--ticks 3 なら 3 件、--dry なら選ぶだけ）
node lab.mjs auto schedule hourly # このPCで 1 時間ごとに 1 件（daily / off）
node lab.mjs auto stop            # 非常停止（auto/STOP）。再開は auto resume（人だけができます）
```

GitHub では `.github/workflows/auto.yml` が 1 時間ごとに 1 件ずつ回します（Secrets に `ANTHROPIC_API_KEY`。止めるのは `auto/STOP` をコミットするか、変数 `LAB_AUTO=off`）。やることの無い回は、最初の `node lab.mjs auto plan` で終わります（Python・Wine・ビルド道具の準備をしないので約 1 分。毎時すべてを準備していたころは Actions の時間を使い切りました）。AI が無いあいだは harden も選びません（足りないテストを AI に頼むので、毎回失敗するだけでした）。失敗した upkeep は 1 日・2 日・4 日…最長 1 週間あけて、あきらめずにまた試します。

**1 回の流れ**：仕事を集める（トークン 0）→ AI が 1 つ選ぶ（理由つき）→ ラボのコマンドで実行 → ラボの検査（アドオンは `go`、ラボ本体の変更はゲートのテスト）→ **別の AI がレビュー**（REJECT なら元に戻す）→ コミットして main に push（ユニットは Release も）→ 台帳に記録、失敗は 1 行の教訓に → 通知。

| 仕事の種類 | どこから来るか | AI がやること |
|---|---|---|
| repair | 最後のテストが落ちたユニット | `maintain -a <ユニット> --to current` で直す |
| upkeep | 前回から `upkeepHours` 経った | 最新の Minecraft に上げて全ユニットを点検・修理 |
| issue | ラベル `auto` の付いた Issue | 作ってプレイテストし、Issue に返事して閉じる |
| release | CHANGELOG にまだ無い変更があるユニット | 版を上げて配布 |
| backlog | `auto/BACKLOG.md` の `- [ ] <依頼>` | `make --playtest` で作る |
| lab | `auto/BACKLOG.md` の `- [ ] lab: <改良>` | **ラボ自体のコードを AI が書き換える**（ゲートのテストが前と同じく通り、床に触れていない時だけ残す） |
| share | 前回の配布からラボ本体が改良された | `share --release` で bds-lab 本体のリリース版を出す |
| playtest / harden | プレイテストしていない・14 日強化していないユニット | 別の AI が壊しにいく／テストを強化 |
| reflect | 数件ごと、または backlog が空 | 台帳と教訓を読み直し、**自分の backlog を書き換え**、教訓を 20 行にまとめる（ラボの改良案もここから出ます） |
| invent | backlog が 3 件未満 | **何を作るかを AI が考えて** backlog に足す |

- **学習**：点数 = 種類の価値 × その種類が台帳で成功した率 × コストの軽さ。失敗した対象は 2^n 時間待ち、4 回続けて失敗したらあきらめます（reflect が別の形で戻すことはあります）。
- **教訓**：失敗すると AI が 1 行の教訓を `auto/LESSONS.md` に書き、以後のすべての `make` がそれを読みます（`LAB_MAKE_CONTEXT`）。
- **トークンを使うのは迷うときだけ**：点数が大差（壊れたユニット、または 2 倍以上の差）なら AI に聞かずに決め、配布の版上げやテストの追記だけの変更はレビューに AI を使いません。Claude CLI 経由の 1 問は Claude Code の前置きを外して送ります（実測 32,488 → 1,339 トークン）。`make --via claude` も道具を 6 つに絞りました（1 ターンあたり実測 36,488 → 9,832 トークン）。
- **持ち場の外は戻す**：アドオンを作る仕事がラボ本体や設定まで書き換えても、ユニットの外の変更は元に戻します（床に触れたら失敗）。`maintain` のように 3 つ中 1 つ直せた仕事は、直せた分だけ残してマージします。
- **失敗したものは残さない**：途中までのユニット・壊れたラボの変更・レビューで却下された変更は、始める前の状態に戻します（git が無くても）。残るのは台帳と教訓だけです。
- **記憶は `auto/`**：`ledger.jsonl`（全タスクの結果・トークン・選んだ理由）・`BACKLOG.md`・`LESSONS.md`。変更と一緒にコミットされるので、CI でも手元でも続きから動きます。

**人が持っている床**（`common/auto-guard.mjs`。AI は書けず、触れた変更はまるごと戻されます）：
- `auto/STOP`：非常停止。あると AI に 1 回も聞かずに止まります。
- `auto/policy.json`：1 日のトークン上限 `dailyTokens`（既定 300 万）・1 件の上限 `taskTokens`（40 万）・`merge`（`auto` = main に直接 / `pr` = プルリクエスト / `local` = push しない）・`release`・`review`・使う仕事の種類 `kinds`・ゲートのテスト `gate`。`node lab.mjs auto policy merge=pr` のように変えられます。

**ターミナルを使える AI が自分で回す**：Claude Code などに「自動で進めて」と頼むと、AGENTS.md に従って `node lab.mjs auto next`（やる 1 件と手順）→ 実行 → `node lab.mjs auto done <id> ok|fail "<教訓>"` を繰り返します。ラボ本体の変更は `done` がゲートを回し、通らなければ元に戻します。

## 自動メンテナンス（`upkeep` ひとつ）

自動メンテナンスの入口は **`node lab.mjs upkeep` だけ**です。順番に全部やって、1 画面で結果を出します。

```
1/4 点検: 問題なし（直したもの 2）              ← maint --fix（一時フォルダ・ロック・ログイン・紛れたトークン…）
2/4 片付け: 1.2 GB 空けました                   ← clean
3/4 最新版: bds: BDS 1.26.60.28 (was 1.26.52.3) ← maintain（全ユニットを最新版で試験、壊れたものは直す）
4/4 ユニット: OK 3, FIXED 1, BROKEN 1
FAIL upkeep (412s) · 次: node lab.mjs bds why -a my_addon
```

- `upkeep --check`：何も変えずに、問題・空けられる量・新しい版が出ているかだけ。
- `upkeep --auto daily`（`weekly` / `off`、`--at 04:00`）：このPCが毎日自分でやる（cron / タスク スケジューラ。結果は通知へ）。
- `--no-ai`：AI を使わずに（モジュールの版の付け替えと制限モードだけ）。`--lab bds` で 1 つのラボだけ。
- ネットワークで調べられなかったものは「ラボの問題」とは分けて出します。自動操縦（`auto`）も 1 日 1 回これを回します。

下の表の `maint`・`clean`・`maintain`・`flaky`・`apidiff`・`undo` は upkeep の中身です。1 つだけやりたいときに使います。

## 自動でやってくれること

| コマンド | やること |
|---|---|
| `node lab.mjs maintain`（upkeep の 3） | **最新版への追従**。ラボを最新の Minecraft にして全ユニットを試験し、動かなくなったものを直します。① モジュールの版の付け替え（beta アドオンが更新で読み込まれなくなる一番多い原因。AI なし・トークン 0）→ ② AI のパッチ（失敗した行と、そのアドオンが使っている API の変更点だけを渡すので少ないトークンで済む。**古いテストを書き換えた修正は受け取りません**）→ ③ **制限モード**（`features.json` のあるアドオンは、まだ動かない機能だけを止めて残りを動かす）。どれでも直らなければ元に戻して BROKEN と報告。本物のクライアントがまだその版に対応していなければ WAIT としてラボを元の版に戻します。前に止めた機能は、次の maintain で動くようになっていれば自動で戻します |
| `node lab.mjs apidiff` | **API の差分**。今の BDS と最新（`--preview` なら次のプレビュー）で Script API の何が消え・変わり・増え・stable になったかと、**各アドオンのどのファイルの何行目が影響を受けるか**。サーバーもトークンも使いません |
| `node lab.mjs watch` | **保存したら自動でテスト**。ファイルを保存するたびに本物のサーバーでテストし、✘ の行だけ出します（`--check` 型検査だけ・`--go` 全部・`--live` 起動したままのサーバーに /reload） |
| `node lab.mjs undo` | **元に戻す**。`make` と `maintain` はアドオンを変える前に自動でチェックポイントを取ります。`undo` で直前に戻り、`undo --list` で一覧、`checkpoint "メモ"` で手動保存。undo 自体も undo できます |
| `LAB_NOTIFY_WEBHOOK` | **スマホに通知**。`.env` に Discord / Slack の Webhook か `https://ntfy.sh/<トピック>` を書くと、make・maintain・最新版チェックの結果が届きます（`node lab.mjs notify` で試験） |
| `--budget` / `LAB_TOKEN_BUDGET` | **トークンの上限**。`make --budget 300000` はそれ以上 AI に聞きません |
| `upkeep --auto daily` | **毎日自動で点検**（`weekly` も可、`--at 04:00` で時刻、`off` で解除）。Linux/Mac は cron、Windows はタスク スケジューラに登録します。GitHub を使わなくても手元で回り続け、結果は通知に届きます（`maintain --schedule daily` は 3 番目だけ） |
| **先取りクライアント** | 新しい Minecraft（プレビューや発売当日）に本物のクライアント部品（bedrock-protocol）が追いついていなくても、直前の版のパケットとサーバーのプロトコル番号で参加して試験します（番号は Mojang の protocol docs から取り、合わなければサーバーの返事を見て自動で合わせます）。だから `maintain --to preview` で「次のアップデートで壊れるもの」を今すぐ調べられます。`LAB_BORROW=0` で従来どおり待ちます |
| `doctor --fix` | 足りない道具のうち、このPCで入れられるもの（root / sudo）をその場で入れて、もう一度調べます |
| `node lab.mjs maint --fix`（upkeep の 1） | **健康診断 19 項目**：試験の一時フォルダ・古い app の結果・終わったベンチの作業フォルダ・古い BDS 用のサーバー置き場・古いチェックポイント・同じ BDS の zip と展開済みの 2 重・colony で取ったもの（古いページの控え、`--deep` で取ったファイルも）・**古いリリースにだけあったファイル**（古い版の update が消さなかったもの。手を入れたものと extras.json に載ったものは残す）・止まったプロセスの記録・ログイン途中のブラウザの記録・空き容量・`.env.local` の権限と除外・ファイルに紛れたトークン・スクリプトの実行権・トークンの形・**同じパック UUID のユニット**（コピーしたフォルダ。ワールドには片方しか入らないので `--fix` で新しい方に別の UUID）・**ラボの知識（kb.json）が古い BDS のもの**（`--fix` で今の BDS から作り直す）・（`--online`）新しい版と**ラボが控えている版の一覧**（BDS の版・モジュールの版）。安全なものは直します。`--only kb,data` で一部だけ。`maintain` と `app run` は軽いものを自動で先に行い、`.github/workflows/maint.yml` が毎週すべてを確かめます |
| `node lab.mjs release` | **1 コマンドで配布**：go（テスト＋品質チェック）が DONE のときだけ、版を 1 つ上げ、TASK.md の「変更」「メンテナンス」から CHANGELOG.md を書き、.mcaddon を作り、GitHub につながっていれば Release まで |
| `node lab.mjs flaky` | **不安定なテストを見つける**：同じテストを何回か新しいサーバーで回し、ときどき落ちる節を FLAKY と出します。`maintain` も 1 回落ちたら 2 回目を回し、通れば FLAKY と報告して AI には渡しません（トークン 0） |
| 自動で stable へ | `maintain` は beta のアドオンを stable のモジュールでも試し、通れば stable に移します（次のアップデートで壊れにくくなる。`undo` で戻せる。`--no-promote` で無効） |
| プレビューの見張り | `maintain --schedule daily --with-preview` で、毎日の点検に加えて **新しいプレビューが出るたびに 1 回だけ** 「次のアップデートで壊れるもの」を調べて通知します |
| テストの抜け | 品質チェックが、自作のコマンド・アイテム・ブロック・エンティティのうち **どのテストも触っていないもの** を挙げます |
| 性能の悪化 | 品質チェックの 1 tick あたりのスクリプト時間をアドオンごとに記録し、自己ベストの 2 倍を超えたら知らせます（予算内でも） |
| 自動チェックポイント | `make` と `maintain` に加え、`mode`・`add`・`lib`・`png` もアドオンを書き換える前に保存を取ります（`undo` で戻る） |
| AI のトークン節約 | ① 前回と同じ失敗なら「SAME failures」と 1 行で言い、同じ種類の直し方の繰り返しを止める ② 同じエラーは ×回数 でまとめる ③ `make` の会話が長くなったら、古い出力と書き終えたファイルの本文を 1 行に縮めて送り直す量を減らす ④ 「できた」のあと同じ失敗が 2 回続けば AI を止める ⑤ `go` はテストと品質チェックを**同時に**別のサーバーで回し、テストが落ちても品質チェックの問題を同じ答えに入れる（1 往復で両方直せる。ビルドが落ちてもサーバー不要の品質チェックは出す） ⑥ 同じ型エラーが何行もあれば 1 行に（行番号を並べる） ⑦ 前回から変わっていない失敗は 1 行に畳む ⑧ tests.txt の打ち間違い（無い操作名は近い名前を提案・壊れた正規表現・数の無い wait・構文エラーの js）はサーバーを起動する前に止める |
| `node lab.mjs bisect` | **壊した変更を自動で特定**：「前は動いていたのに」というとき、アドオンのチェックポイント（make・maintain・mode・add などが自動で取る）を新しい方からさかのぼり、半分ずつ本物のサーバーで試して、**最初に落ちた版・最後に通った版・その間の差分**を出します（直前の変更なら 2 回、古いものでも数回。昔の版が別の理由で落ちていても見失いません）。終わるとアドオンは元のまま。`"<節の見出し>"` でその節だけで判定 |
| `node lab.mjs mutate` | **テストの強さを測る**：自分のコードにわざと小さなバグ（`===`→`!==`、`>=`→`>`、`&&`→`||`、`true`→`false`、呼び出しを 1 行抜く、数を +1）を 1 つずつ入れてテストを回し、**どのテストも気づかなかったバグの行**を出します（そこにテストが足りない）。テストが一度も通らない行は先に挙げます。既定 6 個（`--all` で全部）、終わると元のまま |
| `node lab.mjs why` | **落ちた原因を 1 回の実行で調べる**：落ちた節（指定しなければ最後に落ちた最初の節）を、その前の節ごともう一度動かし、例外・イベント・通った行を記録して読み解きます。例外が出ていれば、アドオン側の行・前後のコード・そのときの変数の値（例：`held=undefined`）を出します。出ていなければ、テストが期待した文の代わりに出た文と、それを出した行・その行での値（例：`have=2 a={n=2}`）、期待した文を出すはずの行が通ったかどうかを出します（例：「src/main.ts:20 が代わりに出し、23 行目は一度も通っていない」）。節が使うのに動かなかったフック（アイテムやブロックの JSON にコンポーネントが無い、など）と、次にやることを 1 行で添えます |
| `node lab.mjs shrink` | **落ちる手順を最小にする**：落ちる節を、同じ落ち方（同じエラー、または同じ期待に同じ文が返る）をする最少の行まで削ります。前の節も削る対象で、残した行が名前を出すプレイヤーは自動で参加させます。報告や読解に使う最小の再現です |
| `node lab.mjs gaps` | **テストが通っていないコード**：カバレッジ付きで 1 回動かし、どのテストも通っていない行を、それを動かすもの（コマンド・アイテムのフック・イベント・メニューのボタン）と、そこへ届くテストの行つきで出します（例：`src/main.ts:33 never ran: /lab:shop → @A cmd /lab:shop · until form · @A form 0`） |
| `node lab.mjs record` | **期待値を書き起こす**：コマンドを新しいサーバーで 2 回動かし、両方で同じ行は `= 行`、数字だけ変わる行は `~ 正規表現` として節にします。スクリプトのエラーは記録せずに知らせ、名前の出たプレイヤーは自動で参加させます。今の動きを写すだけなので、依頼どおりかを確かめてから使います（`--append` で tests.txt に追記） |
| `node lab.mjs chaos` | **本物のプレイヤーがでたらめに遊ぶ**：tests.txt で使っていない名前のプレイヤーが、自作コマンド（でたらめな引数、フォームもでたらめに答える）・アイテム・ブロック・メニュー・イベント・2 人目の参加と退出・再起動を試し、スクリプトのエラーが出るまで遊びます。見つけたら手順を最小まで削り、既存の節の後ろに付けても落ちることを確かめてから、貼れる節として出します（`--append` で追記。バグが直るまで落ち続け、直ったあとは再発を防ぎます）。同じ seed なら同じ遊び方です |
| `node lab.mjs harden` | **AI にテストだけを強化させる**（= `make -a <名前> --harden`）：まずトークンを使わずに、テストが通っていない行（gaps）と見逃す小さなバグ（mutate）を測ります（無ければ AI を呼ばずに終了）。AI はそれを狙った `## harden:` 節を tests.txt の末尾に足すことだけが許され、ほかの変更は元に戻し、既存の節は書き換えさせません。今のコードで落ちる新しい節は SUSPECT として外し（コードのバグか、テストの誤り）、最後に同じバグとカバレッジをもう一度測って「見逃していたバグ 2/4 → 4/4」のように前後を出します |
| `node lab.mjs scan` | **安全確認**：人のアドオンが何をできるか（外部への HTTP 送信・/op /kick /ban /transfer・eval・難読化されたコード・ウォッチドッグの無効化・プレイヤーの入力をそのままコマンドにする所）を、動かす前にファイルの行つきで出します。`import` は取り込むときに自動で調べ、同じ UUID の既存アドオンも知らせます。`.mcaddon` もそのまま調べられます |
| `node lab.mjs i18n` | **翻訳の抜けを埋める**：言語ごとに足りない行を、ほかの言語の文と一緒に出します。`i18n --ai` は足りない行だけを小さなモデルに 1 回で訳させて書き込み（数百トークン）、`i18n ja_JP "item.lab:ruby.name=ルビー"` は手で書き込み、`i18n --add zh_CN` は言語を増やします |
| `node lab.mjs optimize` | **配布物を軽く**：PNG を画素を変えずに圧縮し直し（行ごとに最良のフィルタ・最大圧縮・メタデータ削除・不透明なら RGB）、作業ファイル（psd・bbmodel・Thumbs.db など）と、どこからも使われていないテクスチャを挙げます。**`pack` は前の 2 つを .mcaddon に自動で行います**（元のファイルはそのまま）。`--apply` で元ファイルも圧縮、`--prune` で未使用を削除 |
| kit の自動更新 | 古いアドオンの `src/kit.ts` が**ラボが配った版のまま（手を入れていない）なら、次のビルドで最新の kit に入れ替え**ます（`menu`・`confirm` など新しい関数も使えるように。チェックポイントを取るので `undo` で戻る。書き換えたものには触れません） |
| 重い原因の自動特定 | 品質チェックでスクリプトが重いと出たとき、3 人が参加した状態でプロファイラを回し、**時間を食っている関数と行**をその行に添えます（AI が計測し直すサーバー 1 回分と出力が要らない） |
| stable に移れない理由 | beta のアドオンが stable API で通らないとき、**どの beta 専用 API をどこで使っているか**を 1 行で出します（次のアップデートで最初に壊れる所） |
| ラボの知識の自動更新 | `maintain` が新しい BDS に移ったら、ラボの控え（BDS の版の一覧・モジュールの版・世界の知識 kb.json）も自動で新しくします（トークン 0。`--pr` ならそれもプルリクエストに） |
| コマンドの組み立てミス | 品質チェックが、プレイヤーの名前や入力をそのまま `runCommand` に入れている行を挙げます（空白入りの名前で壊れる・`@a` と打たれると全員が対象になる） |
| エラーの直し方 | テストに出た Script API のよくあるエラー（before-event で世界を変えた・早すぎる world 呼び出し・消えたエンティティ・読み込まれていない場所・無い API など）の下に、直し方を 1 行で出します。AI が調べ回らずに済むぶんトークンが減ります |

**制限モードの書き方**（任意）：アドオンのフォルダに `features.json` を置き、機能ごとに tests.txt の `##` 見出しを結び付けます。コードは kit の `feature('ml', () => { ... })` で包みます（止められていれば動かさず、その Minecraft に無い API で例外が出たら、その機能だけ止めてアドオン全体は動かし続けます）。

```json
{ "features": { "ml": { "ja": "機械学習ボット", "tests": ["ml bots learn"] } }, "off": {} }
```

`maintain` が止めた機能は `"off": { "ml": "BDS 1.26.60.28: <理由>" }` と書かれ、そのテストは SKIP になり、TASK.md の `## Maintenance` に記録されます。TypeScript はビルドが `LAB_FEATURES_OFF` を埋め込み、素の JS は `bp/scripts/lab_features.js` を import します。GitHub では `.github/workflows/latest.yml` が最新版で壊れたものを見つけると、そのまま `maintain --pr` で直してプルリクエスト（`maintain/<版>`）にします（Secrets に AI の鍵）。

## 質を上げる仕組み

- **AI の開発の流れ**（AGENTS.md に書いてあります）：`go` が落ちたら、直す前に `why` で原因を読みます（例外の行と値、または代わりに出た文を出した行と値）。`go` が `DONE` になったら、`gaps`（通っていないコード）・`mutate`（見逃すバグ）・`chaos`（でたらめに遊んで出るエラー）で弱い所を見つけ、1 つずつ `##` の節にして `go` に戻ります。期待値は `record` で書き起こせます。どれもトークンを使わず、本物のサーバーで数回動かすだけです。人が頼むなら `harden` で、この強化を AI に任せられます。
- **`go` の品質チェック（QA）**：テストとは別に、プレイヤー 3 人の同時参加・退出と再参加（再参加でアイテムがまたもらえないか）・自作コマンドへの極端な引数（0・-1・巨大な数・空文字・いないプレイヤー）・コマンドが開いたフォームを閉じたとき・`/reload`・サーバー再起動・何もしない時間を本物のサーバーで回し、スクリプトエラー、コンテンツログの警告、1 tick あたりのスクリプト時間（既定 2ms 以内）、ログの垂れ流し、日英の言語ファイルの抜け、登録されていないカスタムコンポーネント、存在しない戦利品テーブルや未定義アイテムのドロップ、TASK.md の受け入れ条件に対応するテストの有無を調べます。Endstone のプラグインは最後に全コマンドを生成した引数で叩き（コンソールからもプレイヤーからも）、例外が出ないかも調べます。1 つでも問題があれば `DONE` になりません。
- **stable API への自動切り替え**：雛形は beta API で始まりますが、`go` はテストと品質チェックが通ったあと stable API でも型検査とテストを試し、通れば stable のまま仕上げます（ゲームの更新で壊れにくくなります）。beta が要るアドオンは beta のままです（`go --beta` で試さない）。
- **kit（`src/kit.ts`）**：事故が多い処理を、実機で試験済みの小さな関数にしてあります。カスタムコマンド、プレイヤーが忙しいとき（チャットを開いているなど）に待って出し直すフォーム、ボタンと処理を並べるだけのメニュー（`menu`）・はい／いいえ（`confirm`）・入力欄を型付きで受け取るフォーム（`input`）・名前と説明文付きのアイテム（`item`）、全部そろわなければ取らないアイテム消費、あふれたら足元に落とす付与、初回だけの処理、JSON の保存、スコアボード、クールダウン、アイテム・ブロックのカスタムコンポーネント、型エラーにならないカスタムブロック状態の読み書きです。使わない関数はビルドで消えます。beta と stable の両方の API で毎回 selftest しています。
- **ドット絵の自動生成**：`tex=gem:e0115f` のように形と色を指定すると、光と影と縁取りの付いた 16x16 を描きます。形は gem ingot orb apple sword pickaxe axe shovel hoe coin key potion dust stick wand heart star book scroll（アイテム）と block ore bricks planks glass（ブロック）です。 エンティティには顔付きの箱モデル用スキンを描きます。`add` は `states=`（ブロック状態）と `drops=lab:gel*1-2`（戦利品テーブルを作って結び付け）も受け付けます（`node lab.mjs help add`）。
- **本物のクライアント**：`@A join`・`@A cmd /lab:shop`・`@A form ダイヤ`（ボタンは番号でも文字でも指定可）・`@A use`・`@A attack pig` など、12,000 以上の操作をテストに書けます。RTA や目標プランナー（`@A get diamond`）も使えます。
- **静的チェック**：型検査、manifest、UUID、テクスチャ、名前、コンポーネント名（Mojang の一覧と照合）、モデル、JSON UI、BDS がクラッシュする書き方を調べます。
