# app lab: the real Android app shows the addon's JSON UI (BDS never loads rp/ui) and the client's own errors
`node lab.mjs app` = what is ready + the one next step. Flow: `bds go -a <n>` DONE → `app init -a <n>` → write the UI steps in `bds/addons/<n>/app.txt` (`app help`; sample: `bds/addons/jsonui_demo/app.txt`) → `app run -a <n>` → `PASS|FAIL <run>/report.md` + `次:` lines. Read `<run>/shots/*.png` (`fail-line<N>.png` = where line N failed); logs: `logcat-digest.txt` (read first), `logcat-death.txt` (every line around the app's end), `logcat-minecraft.txt`, `server.log`, all steps `run.txt`, `scenario.txt` (what ran).
Every JSON UI screen: `app ui -a <n>` (the addon's rp/ui files → the screens that draw them; `--all` every screen the lab can open: HUD, chat, inventory, pause, settings, the 3 server forms, ~20 block screens, bed, book, sign, NPC, trade, death, disconnect; `--screens id,id`; `--list` = the plan only). One `section` per screen: a failure skips only that section (BACK until the world again). Every picture is also checked for the missing-texture magenta and (OCR) raw translation keys like `item.lab:ruby.name`: noted per screen in the report. The game's content log (JSON UI / pack / script errors only the client sees) is read at every section boundary and tied to it; an ERROR line fails the run (`--allow-client-errors`). Client verbs: `chat`, `tap text <re>` / `until|expect|absent text <re>` (OCR, tesseract), `key E|T|F3|…`, `press W 2000` (held keys), `hold`, `record start|stop`, `perf`, `until|expect|absent clientlog <re>`, `network`, `size 1024x768|reset`, `density`, `cutout tall|hole|…|none`, `mouse tap|move|scroll` (hover, wheel), `pad A|B|…|UP` (controller focus), `screen off|on`, `background`/`foreground`, `trim RUNNING_CRITICAL|…`. Other shapes for every screen: `app ui … --sizes 1024x768,2400x1080 --cutouts tall` (knobs APP_UI_SIZES / APP_UI_CUTOUTS).
Fast start: `app prepare [--account]` makes the device once (fresh AVD, game installed, account, first start to the title screen, snapshot `lab-title` taken as root) and `app run` / `app ui` start from it (seconds; report row `参加` = join link → in the world). It is used only while it fits (same APK as Play offers, emulator, image, cores, RAM, screen, GPU); `--force` remakes it. With `--account` the device before the game (Play Store + account in, first-boot work done) is kept too (`lab-base.json`, cache part `base`): a new Minecraft is made from it (cold boot, no account step, the same Google registration; `APP_BASE=0` = not). A start the license check stops (Play's paywall) leaves `license.txt` (who installed the game, Google registration, token types, Play's library / install record; no values) + `license-log.txt`, then Play's page for the game is read and, when it offers Install / Update, Play installs it (`APP_LICENSE_FIX=page,play`; with `--account` Play installs it from the start anyway).
How the app gets in (1.26, seen on the CI device): BDS 1.26 takes only NetherNet from the app, and joining an address (link, server list, even 127.0.0.1) asks for a Microsoft sign-in; a world on the same network does not. So runs put the BDS on NetherNet LAN (`LAB_TRANSPORT=lan`), start a relay on the device (19132) and a reflector for the LAN discovery broadcasts (UDP 7551 is the game's own port: its outgoing broadcasts are caught by AF_PACKET and sent on to 10.0.2.2:7551 with the game's own address, `lab-relay --reflect`) and `join` = PLAY → Worlds → the "LAN world" (lab / Dedicated Server's world), by the controller: 1.26's new screens (Ore UI) ignore taps on the emulator; directions go as `input gamepad keyevent KEYCODE_DPAD_*`, buttons through the device's own uinput controller held 500 ms (`app/relay/lab-pad.c`; live `pad A`, `APP_PAD_HOLD_MS`); the classic menu is known by its "©Mojang AB" when OCR cannot read its buttons. `APP_TRANSPORT=raknet` = the old join link. Speed knobs (all on by default; DESIGN.md has the costs measured on the device and why): `APP_SHOT=auto|adb|emu` (pictures from the emulator, not the device's 2.5 s screencap), `APP_LIGHT_GFX=0`, `APP_LATCH_UNSIGNALED=0`, `APP_DEBUGGER=1` (`APP_ZERO_FREE=1` is off by default: the emulator's /data is encrypted, zeros land as ciphertext), `APP_WATCHDOG_MS`, `APP_PAD_WAIT_MS`, `APP_TIMEOUT_MULTIPLIER` (Android's ANR deadlines x5, set at prepare).
Friends' worlds and joins by address need a Microsoft sign-in: secrets `MS_EMAIL` (+ `MS_PASSWORD`) → prepare signs the game in on the device (lib/signin.mjs: the menu's Sign In by the device's controller `app/relay/lab-pad.c`, the Xbox WebView's pages told apart by OCR, values typed through stdin) and keeps it in the snapshot; two-step verification is asked on the live issue (`app live --run <run> "code 123456"`). A player without worlds is sent from Play into the new player's flow: prepare puts an own world on the device (lib/world.mjs; `APP_SEED_WORLD=0`; live `world restart`). Verified on the CI device: the real app joined the lab's BDS over NetherNet LAN with no sign-in — directions as key events, buttons held through the device's controller (the game samples them once a frame; ~4 fps), the join's questions (Online play is not rated, Download Resource Packs?) answered by A, the LAN world's card chosen by its white focus ring.
Without a VM (Linux, docker + the kernel's binder): `app run|ui -a <n> --device redroid` (or `APP_DEVICE=redroid`) runs the same `app run` / `app ui` on redroid, the real Android 14 in a container (app/redroid/README.md). `app redroid doctor` = what is missing + the fix; `app redroid setup` (image: redroid + MindTheGapps) → `app redroid prep` once (~8 min: the account written into the stopped device's /data, checkin, Play installs the game so PairIP passes, first start to the title; needs GOOGLE_EMAIL + GOOGLE_AAS_TOKEN) → every run restores that /data by overlay (0.1 s), boots (~10 s), the game at its title ~50 s after the restore (measured on a 2-CPU runner), then `app run` on it (`APP_SERIAL` + `APP_LIVE_DEVICE=1`, the BDS on the docker bridge, the join through the device's relay as on the emulator). `--keep` leaves it up (`app redroid down`) and the next `--device redroid` run uses that device as it is (no restore, no boot; the game started only if it is not running; the APKs pulled again only for a new version; only one started from the same --data and image); one device command at a time (`app/redroid/.lab/device.lock`), Ctrl+C stops the device unless --keep; emulator-only flags (`--account --vending --apk --wipe --window --no-fetch`) are refused. On GitHub: `app ci --device redroid [-a <n>] [--mode run|ui] [--bench] [--keep] [--fresh] [--wait]` (redroid.yml, by hand or a push saying `[redroid ci]`; `--wait` / `app ci watch|fetch <run> --device redroid` = artifacts + notices into `app/runs/gh-<run>/`). In a private repository the prepared device comes from app's encrypted vault (`app redroid seal|open`, AES-256-GCM, key APP_CACHE_KEY or from GOOGLE_AAS_TOKEN) and prep is skipped; `--keep` saves a newly made one (~1 GB of the shared 10 GB cache), `--fresh` makes it again.
Tap positions are screen fractions: `app run … --keep` → `app screen` → read `app/.lab/screen-grid.png` (10 % grid) → `app tap x y` → `app screen`.
Ask a person only for: Android SDK/KVM, the APK (`app token` needs their browser login; never ask for a password) or `app apk <folder>`. Never commit/pack/upload an APK, .so or .env.local (`app guard <dir>`). Test: `node tests/app-offline.mjs`.
On GitHub (no artifacts needed): `node lab.mjs app ci -a <n> [--mode run|ui|ui-all] [--devices 1-4] [--fresh] [--ref <branch>] [--scenario <file>] [--lane <name> --knobs "APP_X=1 .."]` starts the app workflow (prep job: Play's version, the prepared device made once; device jobs in parallel; report job), waits, and fetches the result into `app/runs/gh-<run>/` (`shard-<k>/` per device); `app ci fetch <run>` for a finished one. Runs are parallel by default and `app ci` returns at once (each run its own lane; `--wait` waits and fetches; `app ci watch <run>` later); `--try "APP_X=1" --try "APP_X=2"` starts one run per setting at once (up to 8); the same `--lane` name queues; `--devices 1-8|auto` (auto: 4 for ui modes). Output is anonymized and **result+errors only** by default; `--full` (or `APP_FULL_LOGS=1`) for the verbose logs. The APK, BDS, Play Store and prepared device are cached **only for a private repository and encrypted** (AES-256-GCM, key from `APP_CACHE_KEY` or derived from `GOOGLE_AAS_TOKEN`): never put them anywhere public. `account` is on by default (the game's license check needs the real Play Store and the account).
Resident CI device (restored once, tested again and again): `node lab.mjs app ci --mode hold`, `app live --run <run> --wait`, then `app live --run <run> "run"` (a whole `app run` on that device: BDS up, join, the addon's app.txt; seconds to start) / `--steps <local scenario file>` (nothing to commit) / `"pull <branch>" "run"` (a pushed addon change) / `"ui --all"` / `"last [fail|list|<shot>]"` (that run's report and screens) / `--no-wait` then `--reply <id>`. Live on the CI device (no commit, no rebuild): `node lab.mjs app ci --hold <min> --no-wait` keeps the device up after it is made (a failed one as it is) and after the run; `node lab.mjs app live --run <run> --wait`, then `app live --run <run> "screen"` / `"tap x y [tap|hold|motion]"` / `"key BACK"` / `"sh <device shell>"` / `"logcat 200 <regex>"` / `"input"` / `"windows"` / `"options set k=v"` / `"title 5"` / `"seal"` (keep this state as the prepared device) / `"stop"`; answers and the screen (app/runs/live/) come back in seconds (comments on the private live issue; only the starting user's, device only).
CI facts: private-repo runners are 2 CPU / 7.8 GB / ~14 GB free disk (the workflow frees space in the background; the CPU model changes run to run). The license check (PairIP) refuses a game adb installed even for the buying account: with `--account` Play installs it itself (the default; x86_64 build, no ARM translation; `APP_INSTALL_VIA=adb` = ours) and the check says LICENSED. After the account the device is busy for 10+ minutes (load 10-16 on 2 cores: nothing answers); prepare waits that out once and keeps the calm device as the base. A job stopped mid-step (exit 143, no artifact) → `app ci fetch <run>` writes `explain.txt`; `<run>/host.txt` samples the machine every 15 s.
