## 手順
あなたの作業フォルダ: `{{worktree}}`（枝 `{{branch}}`）。**すべてのコマンドをこのフォルダで実行し、ファイルもこのフォルダの中だけを読み書きする**（`cd {{worktree}} && …`）。ほかのフォルダ（親のチェックアウトや他のレーンの作業フォルダ）には書かない。
1. 確かめる: そのフォルダで `git branch --show-current` が `{{branch}}`、`git merge-base --is-ancestor {{base}} HEAD` が成功（土台 {{base}} から始まっている）。どちらかが違ったら、何も変えずに止めて報告する。
{{#write}}
2. 必要なところを読む。足りない値は推測しない（実機でしか分からないものは「要実測」として報告に書く）。
3. 直す。既存のコードの書き方・名前の付け方・コメントの量に合わせる。
4. 自分のテスト: `{{test}}` が通るまで直す。テストを緩めて通さない。
5. 範囲の検査: `node .fanout/fanout.mjs scope {{name}}` が ✔ になるまで直す（担当の外の変更は元に戻す）。
6. 自分の作業フォルダの枝に commit する（メッセージは日本語で、何をなぜ）。push はしない。他の枝・main に触らない。マージしない。

## 止まる条件（勝手に広げない）
- 担当の外を変えないと目標が達成できない → 変えずに、最後の報告の「依頼」に書いて終える。
- 同じ失敗を 3 回直しても通らない → そこで止めて、分かったことを報告する。
- GitHub Actions を起動しない。gh・`app ci`・外部サービスへの書き込みはしない。秘密（トークン・パスワード）を読まない・出さない。
- 依存を足さない（npm install しない）。大きなファイル（1 MB を超えるもの）を作らない。
